# MAMET ECOSYSTEM ENGINEERING DIRECTIVE

## PURPOSE

This document defines the mandatory engineering workflow for anyone working on this repository, including:

- Human Engineers
- AI Engineers
- Coding Assistants
- Autonomous Agents
- Automation Systems
- Future Engineering Tools

These instructions apply regardless of the programming language, framework, AI model, IDE, or execution environment.

---

# FIRST RULE

DO NOT start analyzing or modifying the source code immediately.

The Source Code is NOT the Source of Truth.

Before doing any engineering task, you MUST read:

```
constitution/README.md
```

Then follow the reading order defined inside the Constitution.

Only after understanding the Constitution may you continue with repository analysis.

---

# SOURCE OF TRUTH

The order of authority is:

Constitution

↓

Vision

↓

Architecture

↓

Engineering Specifications

↓

Repository

↓

Runtime

If any conflict exists, the higher authority always takes precedence.

Never modify the Constitution to match the Repository.

Improve the Repository to match the Constitution.

---

# ENGINEERING WORKFLOW

For every task, follow this order:

1. Understand the user request.

2. Read the relevant Constitution and Architecture documents.

3. Understand the current implementation.

4. Identify the Root Cause.

5. Design the solution.

6. Verify the solution against the Constitution.

7. Implement.

8. Perform self-review.

9. Report the implementation.

Never skip these steps.

---

# ENGINEERING PRINCIPLES

Always:

- Think Constitution First.
- Think Architecture First.
- Think Root Cause First.
- Think Long-Term.
- Build Systems, not just Code.

Never:

- Guess requirements.
- Invent architecture.
- Ignore documentation.
- Create unnecessary complexity.
- Apply repetitive temporary patches.

---

# PATCH POLICY

Do not optimize for the fastest patch.

Optimize for the best long-term architecture.

If multiple patches appear in the same area:

STOP.

Analyze the architecture.

Find the Root Cause.

Implement the permanent solution.

---

# AI ROLE

Your role is Engineering Partner.

You may:

- Analyze
- Explain
- Design
- Review
- Refactor
- Verify
- Recommend
- Implement

You may NOT:

- Change the Constitution.
- Change the project vision.
- Redefine architecture without justification.
- Ignore engineering rules.
- Make final decisions on behalf of the Owner.

The Owner is the highest authority.

---

# SUCCESS CRITERIA

A task is considered complete only when:

✓ Constitution compliant

✓ Architecture compliant

✓ Verified

✓ Modular

✓ Maintainable

✓ Minimal Technical Debt

✓ Reduces Architecture Gap

✓ Supports long-term evolution
