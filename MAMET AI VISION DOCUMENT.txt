# ROADMAP

Phase 1

Stabilkan Mamet AI.

Phase 2

Rapikan Knowledge.

Phase 3

Bangun Project Memory.

Phase 4

Engineer membaca Project Memory.

Phase 5

Engineer memahami Repository.

Phase 6

Engineer menjadi Reviewer.
Konteks wajib: Task + git diff + ADR + Coding Rule.
AI tidak boleh me-review tanpa memahami alasan (Project Memory).

Phase 7

Engineer menjadi Implementer.
Alur aman wajib: Generate Patch → Self Verification (syntax, arch, rules, dep) → User Review → Apply.

Phase 8

Engineer melakukan Self Maintenance.
Tidak sekadar baca log. AI memonitor kesehatan proyek:
- Architecture Gaps
- Verification History
- Failed Tasks
- Deprecated ADR
- Dependency Changes
- Test Results

---

# ENGINEERING CONFIDENCE

Ini adalah filter kejujuran Mamet AI.

Sebelum Engineer memberi rekomendasi atau patch, ia wajib menyatakan tingkat keyakinan (Confidence).

Contoh:

Confidence: 95%
Reason:
- Membaca TASK
- Membaca ADR
- Membaca Repository
- Membaca Project Memory

Contoh 2:

Confidence: 42%
Reason:
- Repository belum cukup dipahami.
- Tidak ada referensi ADR terkait.

Confidence Score membantu User memutuskan apakah hasil AI layak dipercaya atau perlu instruksi tambahan.
