## 🚀 1. Tool Dispatcher (RFC-015) - Shadow Mode (Phase 1-3)
**Konteks:** Menutup celah *Desktop Authority* di mana eksekusi alat (*tools*) berjalan tanpa penegakan fase dari *Engineering Lifecycle* (GAP-NEW-019).
- **Implementasi:**
  - Membuat fondasi `ToolDispatcher` sebagai *Single Choke Point* di `tool_subscriber.ts` (menggantikan *plugin direct execution*).
  - Mengimplementasikan *Stream Interceptor* di `stream_handler.ts` (Phase 3) untuk memonitor injeksi *Terminal Tags* `<terminal>` dan *Function Call* berbasis JSON *markdown* saat *stream* LLM berlangsung.
  - Saat ini murni beroperasi sebagai *Shadow Mode* (hanya observasi dan log). Keputusan `WOULD_DENY` dan `ALLOW` diproduksi sebagai telemetri ke tabel `agent_logs` (event `TOOL_DISPATCHER_AUDIT`) tanpa secara aktual memblokir alur klien (mencegah gangguan UI dari *false positives* prematur).

## 🛠️ 2. Security Hardening & Risk Gate Expansion
**Konteks:** Hasil *Verification Audit* menunjukkan potensi *fail-open vulnerability* pada *dispatcher* dan celah *bypass* komando melalui ragam OS Shell (PowerShell/Linux).
- **Implementasi:**
  - **Context Nullability:** Memberlakukan *Strict Validation* (`null-check`) terhadap objek `RuntimeContext` dalam *try-block* tunggal; menjatuhkan *error-handling* beraliran `DENY_ON_INTERNAL_ERROR` (*fail-closed*).
  - **Recursive Dispatch Protection:** Mengubah deteksi *stack overflow* subagent dari semafor *boolean* global yang rentan `false positive`, menjadi penghitung hierarki `_dispatchDepth` berbatas maksimum (Maks 5).
  - **Risk Gate Expansion:** Melipatgandakan parameter pola interupsi agar sanggup mendeteksi `Remove-Item`, utilitas transfer jaringan (`curl`, `wget`), alat perusak berkas level Kernel Unix (`shred`), serta eksekusi rentetan komando (`&&`, `||`, `;`, `|`).
  - **Telemetry Guarantee:** Mengeksekusi penulisan log asinkron secara *Synchronous* di dalam penanganan eksekusi Edge Function demi memitigasi kegagalan penulisan log saat *timeout*.

## 📈 3. Engineering Metrics & Architecture Alignment (GAP-NEW-007)
**Konteks:** Membangun infrastruktur tabel dan kueri analitik untuk melacak ke-9 *Engineering Metrics* sesuai dengan amanat *Vision Constitution* dan ADR-0007.
- **Implementasi:**
  - Merancang dan memvalidasi migrasi skema melalui artefak `GAP-NEW-007_schema_migration.sql` pada basis data Supabase.
  - Melengkapi persistensi pelacakan tertunda: menambahkan `patch_accepted` pada `engineering_tasks`, `review_confirmed` pada `verification_audit_logs`, dan `bug_category` pada `project_memory_entries`.
  - Mengonstruksi Dasbor SQL Gabungan di `GAP-NEW-007_engineering_metrics_dashboard.sql` yang sukses melacak ke-9 metrik agregat. GAP-NEW-007 resmi berstatus *Resolved*.

## 🛡️ 4. Perancangan RFC-016 (Backend Authoritative Execution Architecture)
**Konteks:** Merumuskan resolusi konseptual terdepan (*next-step*) pasca *Shadow Mode*, guna mendemokratisasi otoritas mutlak dari Svelte Desktop kembali ke Orkestrator (Backend).
- **Rencana Tindakan:**
  - Mengonsepkan implementasi otorisasi dengan *Signed Execution Token* (SET).
  - Merencanakan pengubahan fungsionalitas antarmuka *Desktop* turun derajat menjadi terminal pasif (hanya menginterpretasikan SET dari *backend* tanpa kemampuan inisiasi otonom).
  - Pengonsepan draf tertuang resmi di `RFC-016-BACKEND-AUTHORITATIVE-EXECUTION.md`, menunda realisasi Phase 4 (RFC-015) hingga iterasi evaluasi observasional *Shadow Metrics* selesai.
