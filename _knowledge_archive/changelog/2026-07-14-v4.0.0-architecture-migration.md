# Changelog: Architecture Migration - Mamet OS Ecosystem

## Date: 2026-07-14
## Version: 4.0.0

## Description
Executed a massive Architecture Migration following strict forensic runtime audit of the Mamet OS Ecosystem. The goal was to realign the entire codebase with the newly established Constitutional Directives, enforcing absolute strictness on the Identity Layer, Workspace Layer, Sub-Agent Layer, and Agent Forge registry logic.

## Changes Implemented

### 1. Identity Layer Enforced
- **Removed `OWNER` Concept:** Eliminated all conceptualization of `OWNER` from the system runtime. Identifiers like `ws-owner`, `OWNER mode`, and `OWNER workspace` have been entirely removed.
- **`user_id` as Single Source of Truth:** Assured that all memory, chat, RAG, and workspace access exclusively uses the authenticated Supabase `user_id`.

### 2. Workspace Layer Hardened
- **Allowed Workspaces Only:** Limited active workspace environments strictly to `ws-lite`, `ws-assistant`, and `ws-engineer`.
- **Global EventBus Cross-Pollution Fixed:** Resolved a critical bug where `Agent Forge` hijacked the global workspace state. `WorkspaceManager` instances now utilize a local, isolated `EventBus` to prevent states from leaking across simultaneously mounted applications.
- **Default Fallback:** `ws-assistant` is now the default workspace environment after user login. `ConversationEngine` explicitly uses `ws-assistant` as the fallback layer.

### 3. Agent Forge Stripped of Workspace Status
- **WorkspaceProvider Removed:** Agent Forge, Research App, and Memory App no longer instantiate a `WorkspaceProvider` (removed `lazyWithWrapper` in `AppRegistry`).
- **Metadata Cleared:** `system.json` no longer assigns `workspace` properties to non-workspace applications. Agent Forge is now properly designated as a registry/dashboard, devoid of chat, memory, and RAG tracking.

### 4. Backend Routing Decider Sandboxed
- **Strict Validation:** Updated `routing_decider.ts` edge function to strictly filter incoming `explicitWorkspaceId`. If an unknown workspace string is sent (e.g., `ws-agent-forge` or `global`), it automatically falls back to `ws-assistant`.

### 5. Database Sanitation
- **SQL Migration Executed:** Modified `chats` table to replace all legacy `ws-owner` and `ws-agent-forge` entries with `ws-assistant`.
- **Validation of UUID Enforcement:** Confirmed via script that `user_memories`, `documents`, and `evidence_audit_logs` correctly resisted pollution due to strict UUID constraints; no invalid workspaces existed in those tables.

## Verification
1. **Agent Forge isolation:** Proven via removal of `WorkspaceProvider` wrapper in `AppRegistry.js` and `workspace` property in `system.json`.
2. **Main Orchestrator control:** Enforced securely via `routing_decider.ts`.
3. **Stateless Sub-agents:** Re-established by preventing UI components related to Sub-agents from generating workspace state pollution.
