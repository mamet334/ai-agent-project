## **FASE 1: INFRASTRUKTUR & MONITORING (Supabase Native)**
*Fokus: Membangun sistem yang bisa mendeteksi error sebelum pengguna menyadarinya.*

### **A. Database Setup (Supabase)**
- [x] Buat tabel `monitors` (id, name, url, interval_sec, active, created_at)
- [x] Buat tabel `checks` (id, monitor_id, status_code, response_time_ms, error, checked_at)
- [x] Buat tabel `incidents` (id, monitor_id, status, started_at, resolved_at, webhook_sent)
- [x] Tambahkan index pada `checks(monitor_id, checked_at)` untuk performa *query*.

### **B. Edge Function Health Checker**
- [x] Buat Edge Function baru di `supabase/functions/health-check` (pengganti Next.js).
- [x] Implementasi validasi secret token (Authentication).
- [x] Ambil semua monitor aktif dari Supabase.
- [x] Gunakan `Promise.all` untuk *parallel checking* agar eksekusi cepat.
- [x] Set timeout 5 detik per request (`AbortSignal.timeout(5000)`).
- [x] Simpan hasil *ping* ke tabel `checks`.

### **C. Scheduler & Auto-Cleanup (pg_cron)**
- [x] Manfaatkan Supabase `pg_cron` untuk trigger `/functions/health-check` setiap 15 menit.
- [x] Buat job `pg_cron` mingguan: `DELETE FROM checks WHERE checked_at < NOW() - INTERVAL '30 days'`
- [x] Buat job `pg_cron` bulanan: `DELETE FROM incidents WHERE resolved_at < NOW() - INTERVAL '90 days'`

## **FASE 2: OPTIMASI TOKEN & SELF-HEALING AI (Prioritas Kritis)**
*Fokus: Mencegah tagihan bengkak dan memastikan 99.9% Uptime dengan sistem Fallback.*

### **A. Kompres System Prompt**
- [x] **Ganti Memori Jangka Pendek** dengan versi kompres (tanpa kata sambung berlebih).
- [x] Hapus duplikasi antara memori jangka pendek & panjang.

### **B. Traffic Light Router & Fallback System (Di agent-process)**
- [x] **Tugas Ringan/Cepat** (Parse JSON, Terjemahan, Summarize): Arahkan ke **Groq (Llama 3)**.
- [x] **Tugas Utama** (Riset, Orkestrasi, Koding): Arahkan ke **Gemini 1.5 Flash**.
- [x] **Tugas Kritis/Logika Berat** (Debugging kompleks): Arahkan ke **DeepSeek**.
- [x] **Logika Self-Healing (Fallback):** Jika Gemini mengalami limit/error, tangkap error tersebut (Try-Catch) dan otomatis oper *prompt* ke model cadangan (DeepSeek/Groq) tanpa memberitahu *user* ada *crash*.

### **C. Optimasi RAG (Knowledge Base Token Saver)**
- [ ] Ubah ringkasan di RAG dari paragraf panjang menjadi format poin-poin singkat.
- [ ] Tambahkan filter `tags` agar Mamet tidak membaca dokumen yang salah.
- [ ] Batasi hasil pencarian (*Top-K*) menjadi maksimal 1 atau 2 dokumen teratas saja.

## **FASE 5: MAMET SEBAGAI ASISTEN TEKNISI ANDROID (ADB INTEGRATION)**
*Fokus: Memberikan Mamet kemampuan untuk memodifikasi, mendiagnosis, dan membackup HP Android melalui protokol ADB/Fastboot.*

### **A. Persiapan Infrastruktur Lokal (OS)**
- [ ] Unduh dan ekstrak `Android Platform Tools` (ADB & Fastboot) ke komputer Windows.
- [ ] Daftarkan path folder ADB ke dalam *Environment Variables* (System PATH) Windows agar perintah `adb` bisa dipanggil secara global.

### **B. Pembuatan Tool/Plugin Khusus (`adb_manager`)**
- [ ] Buat file `supabase/functions/agent-process/plugins/adb_manager.ts`.
- [ ] Program fungsi untuk mendeteksi HP: `adb devices` (Mamet bisa tahu HP apa yang sedang dicolok).
- [ ] Program fungsi diagnostik: `adb shell dumpsys battery` (Cek kesehatan baterai) & `adb shell getprop` (Cek spesifikasi HP).

### **C. Injeksi Pengetahuan (System Prompt & Skill)**
- [ ] Ajarkan Mamet perintah *bloatware removal*: `adb shell pm uninstall -k --user 0 [nama.paket]`.
- [ ] Ajarkan Mamet perintah *backup*: `adb pull /sdcard/ [folder_tujuan]`.
- [ ] Ajarkan Mamet perintah *sideloading*: `adb install [path_apk]`.
- [ ] Ajarkan Mamet perintah *screen mirroring* opsional (misal via `scrcpy` jika terinstal).

### **D. Antarmuka (UI) Asisten Teknisi (Opsional)**
- [ ] Buat indikator di Desktop App (AIAgent.jsx) yang menyala hijau 📱 jika ada HP Android yang terdeteksi via USB.
